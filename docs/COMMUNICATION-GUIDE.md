# 가공관리 Pro — 3자 소통 가이드

GPT(총감독) · Cursor(개발) · 오너(사용자) 간 협업 방법

---

## 역할 한 줄 정의

| | 역할 | 하지 않는 것 |
|---|------|-------------|
| **GPT** | 무엇을, 왜, 어떤 순서로 | 코드 직접 수정 |
| **Cursor** | 어떻게 코드로 구현 | 기획·우선순위 임의 결정 |
| **오너** | 승인·테스트·지시 전달 | (선택) 직접 코딩 |

---

## 시나리오별 메시지 예시

### ① 새 기능 시작

**오너 → GPT**
```
1차 틀 완료됐어. HANDOFF.md 기준으로 다음 단계 지시해줘.
우선 납품관리부터 하고 싶어.
```

**GPT → 오너** (지시서 출력)

**오너 → Cursor**
```
GPT 총감독 지시:

(지시서 전체 붙여넣기)

HANDOFF.md와 .cursor/rules 참고해서 구현해줘.
```

---

### ② 구현 완료 보고

**오너 → GPT**
```
[진행 보고]
- 완료: 납품관리 CRUD
- 테스트: 수주 연동 납품수량 업데이트 OK
- 이슈: 없음
- 변경: DeliveryPage.tsx, deliveries.ts, schema.sql

검수하고 다음 지시해줘.
```

---

### ③ 버그/수정 요청

**오너 → GPT**
```
수주 목록에서 거래처 검색이 안 돼. 원인 분석 방향이랑
Cursor 수정 지시서 써줘.
```

**GPT → 오너** (원인 가설 + 수정 지시서)

**오너 → Cursor** (지시서 전달)

## 공유해야 할 파일 (GPT에게)

| 우선순위 | 파일 | 용도 |
|---------|------|------|
| 1 | `HANDOFF.md` | 전체 맥락 |
| 2 | `docs/GPT-DIRECTOR-BRIEF.md` | 첫 대화용 |
| 3 | `supabase/schema.sql` | DB 구조 |
| 4 | `src/lib/constants.ts` | 메뉴·상태값 |
| 5 | 해당 기능 `pages/` + `services/` | 상세 구현 시 |

전체 zip/GitHub 링크를 주되, **HANDOFF.md가 없으면 맥락 전달이 어렵습니다.**

---

## 공유하면 안 되는 것

- `.env` (키 포함)
- `service_role` key
- DB 비밀번호
- 테스트 계정 비밀번호 (별도 안전 채널)

---

## Cursor 규칙 자동 적용

프로젝트에 `.cursor/rules/gakong-pro.mdc`가 있으면  
Cursor가 HANDOFF 원칙(레이어 분리, 범위 통제, UI 기준)을 자동 참고합니다.
